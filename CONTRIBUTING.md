# Contributing to Beryl

Thanks for helping make repositories more inspectable and reliable for people
and coding agents.

## Before opening a pull request

1. Open an issue or discussion for a substantial change so maintainers can
   align on the problem and boundary first.
2. Follow the repository instructions in `AGENTS.md` and the relevant workflow
   under `.beryl/agent/skills/`.
3. Keep changes focused, add or preserve deterministic checks, and run
   `./.beryl/scripts/check.sh` before requesting review.
4. Do not include secrets, credentials, or third-party material that you are
   not authorized to contribute.

you explicitly state otherwise in writing. This follows Section 5 of the
license and does not transfer your copyright.

You represent that you have the right to submit the contribution. If you are
contributing on behalf of an employer or another organization, make sure you
have its authorization first.

We do not currently require a contributor license agreement or signed commits.
Maintainers may introduce a Developer Certificate of Origin or another
contributor-certification process in the future, with clear notice before it
becomes required.

## Review and maintenance

Maintainers review contributions for fit, safety, tests, and project direction.
Submitting a pull request does not create an obligation to merge it or an
entitlement to support.

For help using Beryl, see [SUPPORT.md](./SUPPORT.md). For security reports,
see [SECURITY.md](./SECURITY.md).
